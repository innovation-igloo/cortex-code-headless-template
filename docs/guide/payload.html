04 · Payload

Make it the customer's agent

The template is a scaffold. Here are the extension points you'll actually touch to shape it for a POC: tools, hooks, permissions, and configuration.

Custom tools

Add an in-process tool

In-process MCP tools run inside the service process, so they have direct access to your app state. This is the main thing you'll extend, in tools.py.

from cortex_code_agent_sdk import tool, create_sdk_mcp_server

@tool("lookup_order", "Look up an order by id", {"order_id": str})
async def lookup_order(args):
    oid = args["order_id"]
    # ... your logic (call an API, query app state, etc.)
    return {"content": [{"type": "text", "text": f"Order {oid}: shipped"}]}

def build_tool_server():
    return create_sdk_mcp_server("poc_tools", tools=[lookup_order])

The agent addresses it as mcp__poc_tools__lookup_order. The built-in Snowflake query tool is SQL.

Guardrails

Permissions & hooks

The default can_use_tool policy auto-allows read tools and denies non-allowlisted state-changing tools (Bash, Write, Edit). Widen it via HEADLESS_AGENT_ALLOWED_TOOLS or edit permissions.py.

Hooks in hooks.py fire on PreToolUse / PostToolUse for audit logging — a good place to add per-POC redaction, metrics, or approval gates.

⚠ Bypass + allowlist footgun
With permission_mode = bypassPermissions, do not also set an allowlist — CLI 1.1.x will permanently block the SQL tool. The template clears the allowlist automatically in bypass mode.
