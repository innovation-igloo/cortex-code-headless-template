Making Cortex inference work from SPCS

This is the part that isn't obvious. Getting the agent to authenticate to Cortex from inside a container took clearing five separate blockers. Here is each one and the fix, so you clear them in one pass.

The error progression

Five blockers, in the order they bite

Each fix reveals the next error. All five must be true for a turn to succeed.

#SymptomRoot causeFix
1No Snowflake connection availableThe CLI needs a connection file; it doesn't read SNOWFLAKE_CONNECTIONS_* env vars in-container.auth.py writes config.toml.
2Instant fail, error 395092The SPCS session token is not supported for the Cortex inference path.Use a PAT, not the SPCS token.
3IP ... is not allowed to access SnowflakeAn account network policy rejects the compute-pool IP.Auth policy with NETWORK_POLICY_EVALUATION = NOT_ENFORCED on the service user.
4Session no longer existsPAT auth over the internal SPCS host doesn't work.Use the external account host (no internal host line).
5connection interrupted while streamingThe inference response streams from a host a narrow egress list misses.EAI egress ('0.0.0.0:80','0.0.0.0:443').
✓ Result
With all five cleared, a turn returns subtype: "success" and streams the answer.
The recipe

What must be true

  1. PAT auth. A dedicated TYPE=SERVICE user with a Programmatic Access Token. The SPCS OAuth token cannot reach Cortex inference.
  2. Auth-policy bypass. Attach an authentication policy with PAT_POLICY = (NETWORK_POLICY_EVALUATION = NOT_ENFORCED) so the container's IP isn't rejected. This does not touch the account network policy.
  3. External host. Connect via the account (account.snowflakecomputing.com), not the SPCS-internal SNOWFLAKE_HOST.
  4. Wide egress. An External Access Integration whose network rule allows 0.0.0.0:80 and 0.0.0.0:443, attached to the service.
  5. Connection files. The container writes config.toml (the SQL connection) and cortex/settings.json (cortexAgentConnectionName, the inference connection).
Setup

The identity + egress SQL

From deploy/00_setup.sql. The service user and its auth policy are the two pieces that unlock SPCS.

-- dedicated service user (programmatic auth only)
CREATE USER CORTEX_HEADLESS_SVC TYPE = SERVICE
  DEFAULT_ROLE = SYSADMIN DEFAULT_WAREHOUSE = CORTEX_HEADLESS_WH;
GRANT ROLE SYSADMIN TO USER CORTEX_HEADLESS_SVC;

-- let this user's PAT skip the account network policy IP check
CREATE AUTHENTICATION POLICY SVC_PAT_POLICY
  AUTHENTICATION_METHODS = ('PROGRAMMATIC_ACCESS_TOKEN')
  PAT_POLICY = ( NETWORK_POLICY_EVALUATION = NOT_ENFORCED );
ALTER USER CORTEX_HEADLESS_SVC SET AUTHENTICATION POLICY SVC_PAT_POLICY;

-- egress so the inference stream can flow
CREATE NETWORK RULE SNOWFLAKE_EGRESS TYPE = HOST_PORT MODE = EGRESS
  VALUE_LIST = ('0.0.0.0:80','0.0.0.0:443');
CREATE EXTERNAL ACCESS INTEGRATION CORTEX_HEADLESS_EAI
  ALLOWED_NETWORK_RULES = (SNOWFLAKE_EGRESS) ENABLED = TRUE;
⚠ Why not the SPCS OAuth token?
It authenticates for standard SQL, but the Cortex Agent / inference path rejects it (395092). PAT is the supported route for headless Cortex Code in SPCS.
In the container

The connection files that get written

auth.py materializes these at startup from the injected env + PAT secret. Note: external account, no host line.

# ~/.snowflake/config.toml
default_connection_name = "poc"
[connections.poc]
account = "MYORG-MYACCT"
authenticator = "programmatic_access_token"
password = "<PAT>"
role = "SYSADMIN"
warehouse = "CORTEX_HEADLESS_WH"

# ~/.snowflake/cortex/settings.json  (the inference connection)
{ "cortexAgentConnectionName": "poc" }
