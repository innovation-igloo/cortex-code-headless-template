03 · Launch Sequence

From image to a live endpoint

The copy-paste runbook. Assumes the Pre-Flight identity + egress objects exist. Prereqs: the cortex CLI, snow CLI, and Docker with buildx.

1 Stand up infrastructure

Creates the database, schema, image repo, compute pool, warehouse, service user + auth-policy, secret, and EAI.

snow sql -f deploy/00_setup.sql
# note the repository_url from SHOW IMAGE REPOSITORIES

Then mint a PAT for the service user and store it in the secret:

-- returns token_secret; put it in the AGENT_PAT secret
ALTER USER CORTEX_HEADLESS_SVC ADD PROGRAMMATIC ACCESS TOKEN COCO_PAT
  ROLE_RESTRICTION = SYSADMIN DAYS_TO_EXPIRY = 90;

2 Build & push the image

Build for the SPCS node architecture and push to the account image repo.

export REPO_URL=<repository_url>
snow spcs image-registry login
docker build --platform linux/amd64 -t "$REPO_URL/cortex-headless-agent:latest" .
docker push "$REPO_URL/cortex-headless-agent:latest"
⚠ Registry login expires
If push returns an authorization failure, re-run snow spcs image-registry login and push again.

3 Create the service

Edit the USING (...) values in deploy/20_create_service.sql (image URL, org-account), then:

snow sql -f deploy/20_create_service.sql
# wait for READY, then get the public URL
SHOW ENDPOINTS IN SERVICE CORTEX_HEADLESS_AGENT;

The service is created with EXTERNAL_ACCESS_INTEGRATIONS = (CORTEX_HEADLESS_EAI) and the PAT secret injected. Grant a consumer role the endpoint's service role if others need access:

GRANT SERVICE ROLE CORTEX_HEADLESS_AGENT!api_user TO ROLE <consumer_role>;

4 Call the API

The public endpoint uses the SPCS ingress OAuth flow. Send the PAT as Snowflake Token="..." and follow the redirect with a cookie jar to establish the session, then call the API.

URL="https://<ingress-host>.snowflakecomputing.app"
PAT="<PAT for a user with the api_user service role>"

# 1) prime the ingress OAuth session cookie (note -L and the cookie jar)
curl -sL -c cj.txt -b cj.txt "$URL/ready" -H "Authorization: Snowflake Token=\"$PAT\""

# 2) hit the streaming chat API
curl -N -b cj.txt -X POST "$URL/chat" \
  -H "Authorization: Snowflake Token=\"$PAT\"" -H "Content-Type: application/json" \
  -d '{"prompt":"say pong","session_id":"demo"}'
✓ Expected
data: {"type": "text", "text": "pong"}
data: {"type": "result", "subtype": "success", "num_turns": 1}
⚠ Gotchas that look like a broken service
A raw Authorization: Bearer <PAT> returns a 302 redirect. Not following the redirect (no -L/cookie jar) returns 500 {"responseType":"FAULT"}. Neither is a service failure — both are the ingress auth handshake.

5 Operate

  • Logs: SELECT SYSTEM$GET_SERVICE_LOGS('CORTEX_HEADLESS_AGENT', 0, 'agent', 200);
  • Redeploy a new image: ALTER SERVICE ... FROM SPECIFICATION $$...$$
  • Rotate the PAT: update the AGENT_PAT secret, then ALTER SERVICE ... SUSPEND; RESUME; — env-injected secrets don't hot-reload.
  • Tear down: DROP SERVICE IF EXISTS CORTEX_HEADLESS_AGENT;
